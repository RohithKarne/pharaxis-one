# Postmortem — the Actor reported CLEAN having run three of five steps — 6th Aug 2026

Written under SOP §37.1. Blameless: this names mechanisms, not people.

> **The Actor harness was retired on 7th Aug 2026** on Rohith's instruction — too
> heavy for the team to carry. `apps/cp-portal/actor/` is deleted and the code
> paths named below no longer exist. **This postmortem stays.** §37.1 records that
> we stated something untrue, and deleting the code does not undo having said it.
> The generalisable lesson at the foot outlived the tool it came from.
>
> One item below is now moot: Kiranmai's structural fix — a chain declaring its
> expected step count — was owed against a harness that no longer exists.

## What we said

The Actor harness, on two consecutive runs, printed:

```
clean    Unpublished news stays invisible until it is published
```

and wrote `"outcome": "CLEAN"` into `actor/journals/journal-*.json`, which is the
artefact the reporting routine is designed to file Jira tickets from.

The chain's stated claim is in its own `question` field: *"Can a doctor see a news
post that nobody has approved yet?"* — a claim about the full draft → publish →
visible sequence.

## What was true

The chain ran **three of its five steps**. It never published anything and never
checked the post-publication state.

`apps/cp-portal/backend/routes/admin/news.js` returns the created row nested:
`{ post: { id, ... } }`. The chain read `draft.body?.id ?? draft.body?.postId`.
Both were `undefined`. The publish half was wrapped in `if (postId) { … }`, so it
was skipped in silence, and the chain returned its default outcome of `CLEAN`.

**Half the assertion was never tested, and the artefact said it passed.**

## How long it stood

Two runs, roughly forty minutes, on 6th Aug 2026. Nothing downstream consumed it —
the reporting routine that would have turned this into a Jira ticket does not exist
yet.

Caught while reading the step-by-step trace for a different purpose. The step count
looked short. **Nothing in the summary output would ever have revealed it** — the
summary said 3 chains, 0 findings, which was accurate and useless.

## Why the check did not catch it

1. **A skip was inferred from a missing value.** `if (postId)` treats "I could not
   find the id" and "there is no work to do here" as the same condition. They are
   opposite conditions, and only one of them is safe.
2. **The response shape was assumed, not read.** The endpoint was checked for its
   request contract and its status code; the shape of what it returns was inferred
   from other endpoints in the same API. Those endpoints are not consistent with
   each other — a separate finding surfaced by this same run.
3. **CLEAN was the default outcome.** A chain that falls off its own end returns
   clean. The absence of a finding was treated as evidence of correctness rather
   than as the absence of evidence.
4. **Nobody read it before it ran.** The harness went from keyboard to executing
   against a database with no second reader. The bug is visible in a careful read
   of ten lines against the endpoint's actual response.

## Systemic fix

**Shipped 6th Aug 2026** in `apps/cp-portal/actor/chains/news-review-gate.js`: the
id is read from the correct location, and — the part that matters — a missing id
now **raises a finding and returns FINDING** rather than skipping:

> Reporting CLEAN here would mean the chain silently covered half of what it claims
> to cover.

**Also shipped:** SOP §37.2 *Review before it runs*, whose third reviewer question
is "could this fail silently?", written directly out of this failure.

**Still owed, not yet built:** Kiranmai's structural fix — a chain declares how many
steps it expects, and a short run is itself a finding. The per-chain fix above
addresses this instance; the structural one addresses the class. **Every chain added
before it exists is another chance for a quiet half-run.** Roughly half a day, and
it should land before breadth work begins.

## The generalisable lesson

**"0 findings" from an automated harness is a claim, and it needs its own evidence.**

A tool built to catch silent success produced silent success on its second day. The
property that makes the failure class dangerous — it looks exactly like working —
does not exempt the detector.

The working habit that caught it, now standard: **read the trace, not the summary.**
A summary is generated by the same code whose correctness is in question.
